# Flatpak

## Obiettivo

Distribuire GitHandler anche come Flatpak: un bundle installabile e aggiornabile dal centro software
della distribuzione, con il sandbox di Chromium acceso anche dentro il sandbox di Flatpak.

## Contesto

-   Gli altri pacchetti (`build/package-deb.sh`, `build/package-appimage.sh`, `build/package-rpm.sh`)
    condividono lo stesso payload: il runtime `node_modules/electron/dist` più `dist/` e un
    `package.json` ridotto ai campi che servono a Electron.
-   `build/githandler.apparmor` esiste perché Ubuntu 24.04 limita i namespace utente non privilegiati
    e il setuid helper è il modo per tenere il sandbox. Dentro Flatpak non serve: i namespace li
    fornisce il runtime.
-   La base app `org.electronjs.Electron2.BaseApp` porta `zypak-wrapper`, che adatta il modello di
    processi di Chromium al sandbox.
-   Su questa macchina `flatpak` e `flatpak-builder` non sono installati e non hanno un candidato
    apt: tutto ciò che si può fare è scrivere e controllare la sintassi.

## Scelte

-   **Manifest statico + script che lo assembla**: `build/githandler.flatpak.yml` è versionato, ma
    non viene eseguito da `build/`. Lo script copia manifest, launcher, icone, licenza e desktop
    entry in una cartella temporanea insieme all'archivio del payload, così `build/` non contiene
    binari e il manifest resta leggibile nel repository.
-   **Payload come un solo archivio**: `type: file, path: githandler.tar`; il manifest lo scompatta
    in `/app/githandler` con un `tar -xf`. Un `type: dir` locale non è una sorgente portabile.
-   **Runtime e base 24.08**: è la coppia `org.freedesktop.Platform` /
    `org.electronjs.Electron2.BaseApp` che esiste da più tempo; l'app-id è
    `io.github.emaxlele.GitHandler` e comanda anche i nomi di desktop entry, icona e metainfo.
-   **Nessun `--no-sandbox`**: `build/githandler-flatpak.sh` usa `zypak-wrapper` e basta. Il ripiego
    del `.deb` e dell'AppImage serve dove i namespace utente sono limitati dal sistema, condizione
    che dentro Flatpak non si presenta.
-   **Permessi il più stretti possibile**: `home`, `/media`, `/run/media`, `ssh-auth`, notifiche,
    `StatusNotifierWatcher`, `secrets`, Wayland con ripiego X11, `ipc` e `dri`. Niente `host`.
-   **Metainfo AppStream generato**: versione e data vengono da `package.json`, così il file nella
    cartella di build non invecchia.

## Rischi

-   `--install-deps-from=flathub` richiede un remoto `flathub` configurato: senza, flatpak-builder
    si ferma e l'errore è il suo, non nostro. Il README dice quali runtime installare.
-   La versione 24.08 può invecchiare: quando la base app passa a una versione nuova vanno cambiati
    `runtime-version` e `base-version` insieme.
-   Il payload include il sandbox setuid di Electron, che dentro Flatpak non viene usato: occupa
    spazio nel bundle senza servire. Toglierlo richiederebbe di distinguere i payload per formato.
-   Un test vero richiede Flatpak installato: la prima build potrebbe chiedere correzioni al
    manifest che qui non si possono vedere.

## Verifica

```bash
bash -n build/package-flatpak.sh build/githandler-flatpak.sh
python3 -c "import yaml; yaml.safe_load(open('build/githandler.flatpak.yml'))"
# su una macchina con flatpak-builder:
npm run flatpak
flatpak install --user ./release/GitHandler-0.10.0-x86_64.flatpak
```

## Resume prompt

GitHandler ships a Flatpak: `build/githandler.flatpak.yml` (app-id `io.github.emaxlele.GitHandler`,
freedesktop 24.08 + `org.electronjs.Electron2.BaseApp`), `build/githandler-flatpak.sh` launching
Electron through `zypak-wrapper`, and `build/package-flatpak.sh` (`npm run flatpak`) which stages the
payload tarball, generates desktop entry and AppStream metainfo and produces
`release/GitHandler-<version>-x86_64.flatpak`. The build was never run because `flatpak-builder` is
not available on the development machine: install it, run `npm run flatpak`, fix the manifest if the
build complains, then update CHANGELOG, TODO, ROADMAP, README and `docs/registro-attivita.md`.
