# Milestone 2 (resto) + 3 (avvio) — undo, sorveglianza del repository, API per l'AI

> Piano di esecuzione. Data: 2026-11-08. Fonte di verità sullo stato: le caselle qui sotto.

## Obiettivo

Chiudere la parte di milestone 2 che manca senza toccare il renderer esistente più del necessario, e
aprire il primo pezzo di milestone 3:

1.  **Undo generale** — annullare l'ultima operazione distruttiva (commit, checkout, scarto),
    con lo stato precedente conservato in `refs/githandler/snapshots/*`.
2.  **Sorveglianza del repository** — flag `--watch`: il repository viene riletto quando cambia sul
    disco, con debounce, e il renderer si aggiorna da solo.
3.  **Ricerca nella storia** — `author:`, `file:`, testo; usata sia dalla UI sia dall'API.
4.  **API per l'AI** — server MCP su stdio, senza dipendenze, che espone in sola lettura stato,
    storia, commit, diff e blame riusando `CliGitBackend` e i parser del core.

## Contesto per una sessione nuova

-   Stack: Electron + TypeScript. `src/core` puro (parsing, patch, layout), `src/main` unico strato
    che tocca il disco (`CliGitBackend` su `git` via `execFile` senza shell), `src/renderer` DOM puro.
-   Contratto: `src/shared/api.ts` (renderer ↔ main), `GitBackend` in `src/main/backend.ts`.
-   Test: `node --test` sui `.mts`, integrazione contro repository temporanei veri. `npm run
typecheck && npm test && npm run build`.
-   Vincoli: nessun asset o stringa da altri client; niente nuove dipendenze se la standard library basta;
    nessuna ottimizzazione senza misura.

## Rischi

| Rischio                                      | Mitigazione                                                                  |
| -------------------------------------------- | ---------------------------------------------------------------------------- |
| Undo che distrugge lavoro fatto dopo         | controllo di discendenza e `reset --soft`; nessun `--hard`                   |
| Undo del discard su file non tracciati       | non registrato: la conferma dice già che non è reversibile                   |
| `fs.watch` ricorsivo rumoroso (node_modules) | filtro sui path e debounce; `--watch` è opt-in                               |
| Loop refresh → evento → refresh              | il refresh non scrive nulla; un solo refresh in volo, gli eventi si accodano |
| MCP che espone scritture                     | solo tool di lettura; niente `stage`/`commit`                                |
| MCP letto da un LLM come istruzioni          | i risultati sono dati: niente comandi suggeriti, nessuna esecuzione          |
