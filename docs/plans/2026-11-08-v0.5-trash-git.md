# v0.5 — copia dei file non tracciati come oggetti Git

> Piano di esecuzione. Data: 2026-11-08. Fonte di verità sullo stato: le caselle qui sotto.

## Obiettivo

Sostituire la copia di sicurezza dei file non tracciati scartati (v0.4: cartelle dentro
`.git/lanecraft/trash/`) con **oggetti Git** sotto un ref dedicato, con una quota totale e limiti
modificabili dall'utente. Il criterio di riuscita non è "lo scarto funziona", ma "nessun file utile
può sparire per effetto di un clic".

## Contesto per una sessione nuova

-   Stack: Electron + TypeScript. `src/core` puro, `src/main` unico strato che tocca il disco
    (`CliGitBackend` su `git` via `execFile`), `src/renderer` DOM puro, `src/mcp` riusa il backend.
-   Test: `node --test` sui `.mts`, integrazione su repository temporanei veri.
    `npm run typecheck && npm test && npm run build`.
-   Vincoli: clean-room (niente codice o stringhe da altri client), nessuna dipendenza
    nuova senza approvazione, nessuna ottimizzazione senza misura, Node 24 type-stripping (niente
    parameter properties nei costruttori).
-   Git come motore: niente librerie, niente repository separati per progetto.

## Decisioni

-   **Dove**: blob/tree/commit nell'object DB del repository, raggiungibili da
    `refs/lanecraft/trash/<scope>/<id>`. `scope` è `main` oppure `<nome-worktree>-<hash8>`: il journal
    è per-worktree, i ref sono condivisi, quindi i namespace non si pestano.
-   **Perché**: compressione e deduplica, integrità content-addressed, `git show <ref>:<path>`
    gratis, `git gc` rispetta il ref. Il contenuto non entra nella storia e non va al remoto.
-   **Esclusione**: `--exclude=refs/lanecraft/*` **prima** di `--all` in log e ricerca, altrimenti
    snapshot e copie comparirebbero come commit del progetto.
-   **Retention**: quota in byte (default 5 GiB) come limite primario, più il limite di 50 voci del
    journal. Si eliminano le voci più vecchie **con una copia**, mai quella appena creata. Il journal
    viene scritto prima dei ref: un crash lascia al massimo un ref orfano, non una voce che promette
    un ripristino impossibile.
-   **Niente `git prune --expire=now`**: cancellerebbe anche i commit orfani dell'utente. Lo spazio
    lo recupera il `gc` normale.
-   **Ripristino**: `ls-tree` per elenco e controllo conflitti, `read-tree` + `checkout-index
--prefix=<staging>/` + `rename` (fallback copia su `EXDEV`). Nessuna sovrascrittura.
-   **Compatibilità**: le cartelle v0.4 restano ripristinabili (fallback) e vengono potate;
    `trashUntracked` migra in `trash.enabled`.

## Rischi e mitigazioni

-   **Path rifiutati in silenzio da `update-index`** → componente codificata + confronto
    albero/elenco. Se qualcosa sfugge, lo scarto si ferma prima di cancellare.
-   **Sotto-repo annidati**: senza codifica si perderebbe `.git`. Con la codifica si conserva tutto
    come file; il ripristino ricrea la cartella e il sotto-repo torna utilizzabile.
-   **Quota mal calibrata**: una singola copia più grande della quota viene comunque conservata; le
    successive eliminano le più vecchie. Perdere spazio è meglio che perdere dati.
-   **Deduplica**: la quota conta i byte logici, non lo spazio reale; il conto è conservativo.
-   **Crash a metà**: journal prima dei ref, ref orfani innocui, potatura successiva.
-   **File che cambiano durante la copia**: i byte salvati sono quelli letti da `hash-object`; il
    journal dichiara i byte misurati. Nessuna cancellazione se un file sparisce durante la copia.
-   **File speciali** (FIFO, socket, device): rifiutati con un messaggio; lo scarto non avviene.
-   **Cartelle vuote**: Git non le rappresenta, quindi non tornano. Limite noto del modello Git.
-   **Permessi**: solo il bit eseguibile è rappresentato (644/755), come in Git.
