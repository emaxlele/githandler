# Piano v0.8 — checkout di un commit, benvenuto, creazione, clone e account collegati

> Obiettivo: chiudere i buchi di flusso attorno al repository. Checkout di un commit (oltre che di un
> ramo), creazione di un repository nuovo con identità locale, clone da URL e dagli account collegati
> (GitHub, GitLab, Gitea/Forgejo, Bitbucket), gestione degli account con token modificabile, cartella
> di base scelta dall'utente, schermata di benvenuto al posto del dialog di sistema, «+» allineato.
> Ultima modifica: 2026-11-08

## Contesto

-   Progetto `~/Projects/githandler`, v0.7 (`7ba4c17`): renderer in `src/renderer/app.ts` (file unico,
    funzioni per area), contratto `src/shared/api.ts`, preload `src/preload/index.ts`, main
    `src/main/index.ts`, backend `src/main/backend.ts`, `runGit` in `src/main/git.ts`, core puro in
    `src/core/*` con test `node --test` in `tests/*.test.mts`.
-   Oggi `boot()` chiama `openRepository()` senza path: il main apre il dialog di sistema. Va cambiato:
    senza repository si mostra il benvenuto; il dialog si apre solo da un pulsante.
-   `checkout(branch)` esiste (menu del ramo); manca `git switch --detach <sha>` dal menu del commit.
-   `Settings` ha solo `api` e `trash`: va aggiunta la cartella di base, letta da main e renderer.
-   Il backend non ha un modo per `init` e `clone`: non c'è un repository aperto su cui operare, quindi
    servono funzioni a sé che parlano con `runGit` dalla cartella genitore.
-   Credenziali: l'app non scrive segreti. Il token resta in memoria; per git si usa `GIT_ASKPASS`
    (script generico che legge `GITHANDLER_USER`/`GITHANDLER_TOKEN` dall'ambiente, non dal file), e se
    l'utente ha un credential helper configurato il token viene anche consegnato con
    `git credential approve` così git lo ritrova. Nessun token in argv, log, file dell'app o screenshot.

## Rischi

-   Token in memoria: se l'utente non ha un credential helper deve reinserirlo a ogni avvio. Va detto
    nell'interfaccia, non scoperto.
-   `git clone` può durare minuti: timeout 10 minuti, nessun output in streaming (solo esito), il
    pulsante si disabilita finché non finisce.
-   La cartella di base può non esistere più: va verificata al momento dell'uso e, se manca, si torna
    alla home.
-   Chiusura dell'ultima scheda: il main deve dimenticare il backend e fermare il watcher, altrimenti
    gli eventi continuano ad arrivare a una sessione che non c'è più.
