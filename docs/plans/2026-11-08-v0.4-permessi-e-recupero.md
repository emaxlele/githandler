# v0.4 — permessi dell'API e recupero dei file non tracciati

> Piano di esecuzione. Data: 2026-11-08. Fonte di verità sullo stato: le caselle qui sotto.

## Obiettivo

Chiudere le voci della milestone 2/3 rimaste dal piano precedente, con due aggiunte nate da un
bisogno concreto (perdita di file non tracciati e controllo sugli accessi dell'AI):

1.  **Permessi dell'API configurabili** — default spento; modi `off` / `read` / `all` / `custom`,
    condivisi fra UI e server MCP, riletti a ogni richiesta.
2.  **Recupero dei file non tracciati scartati** — copia di sicurezza in `.git/gitcraft/trash/`
    prima della cancellazione, ripristinabile con `Annulla`, con limiti espliciti.
3.  **Blame nella UI** — pannello virtualizzato con commit, autore e testo per riga.
4.  **Paginazione della storia** — pagine da 2.000 commit con caricamento automatico in fondo.

## Contesto per una sessione nuova

-   Stack: Electron + TypeScript. `src/core` puro (parsing, patch, layout, impostazioni),
    `src/main` unico strato che tocca il disco (`CliGitBackend` su `git` via `execFile` senza shell),
    `src/renderer` DOM puro. Il server MCP importa lo stesso backend.
-   Contratto: `src/shared/api.ts` (renderer ↔ main). Il renderer non è una fonte attendibile:
    `app:settings:save` normalizza prima di scrivere.
-   Test: `node --test` sui `.mts` con integrazione su repository temporanei veri.
    `npm run typecheck && npm test && npm run build`.
-   Vincoli: nessun asset o stringa da altri client; niente nuove dipendenze se basta la standard library;
    nessuna ottimizzazione senza misura; Node 24 type-stripping (niente parameter properties nei
    costruttori).

## Rischi

-   **Spazio su disco**: la copia può duplicare una cartella di build. Mitigazione: limiti bassi e
    rifiuto esplicito oltre soglia, con rimando alle impostazioni.
-   **Percorsi ostili nel journal**: un `trash` con `../` farebbe uscire dal repository. Mitigazione:
    regex sul nome e validazione dei path già esistente.
-   **Policy letta di frequente**: un file di impostazioni su rete lenta. Mitigazione: lettura per
    richiesta, non per tool; il file è piccolo e locale.
-   **Paginazione e grafo**: il layout viene ricalcolato sull'insieme caricato; con molte pagine il
    costo cresce. Mitigazione: pagine da 2.000 e caricamento solo su richiesta dell'utente.
